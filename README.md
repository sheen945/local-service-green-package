# local-service-green-package

> 把本机常驻服务类程序（new-api.exe、各种 xxx.exe 网关/服务）打包成「解压后双击即用」的绿色免安装包，发给朋友或拷到另一台电脑直接用，并配套一份「丢给 AI 就能部署」的提示词。触发词：打包给朋友、绿色版、免安装包、解压即用、把 XXX 打包发给别人、拷到另一台电脑用、一键部署提示词、给别人装一套。

## 安装

把本仓库的目录内容复制到你的技能目录下，文件夹名保持 `local-service-green-package`：

- WorkBuddy / CodeBuddy：`~/.workbuddy/skills/local-service-green-package/`
- Claude Code：`~/.claude/skills/local-service-green-package/`

重启会话后即可通过触发词自动匹配。

# 本机服务绿色交付包

把「跑在你自己电脑上的服务/工具」打包成别人解压双击就能用的包。适用于 new-api 这类
本机常驻服务，也适用于任何「一个 exe + 一个配置/数据文件 + 需要后台常驻」的自建工具。

## 交付包标准结构

```
XXX-本地服务-给朋友-<日期>.zip        ← 解压后是一个文件夹
  └── XXX-本地服务/
        ├── 启动器.exe               ← 双击这个（PyInstaller --onefile --noconsole 打包）
        ├── 服务主程序.exe            ← 后端本体
        ├── 配置/data 文件            ← 数据库、配置等
        ├── 使用说明.txt              ← 给使用者看，UTF-8 BOM 编码（记事本不乱码）
        └── AI部署提示词.md           ← 丢给 AI，让它带使用者装好
```

顶层套一层文件夹，避免解压后文件散落一地。

## 标准流程

1. **摸清用户要带什么**（必问，别猜）：密钥是否随包、是否带历史数据、功能是否全保留、
   目标机器形态（免安装/安装）、要不要开机自启。给出的选项要标推荐项 + 理由。
2. **造干净的数据文件**：用 `sqlite3` 的 `backup()` 做快照（自动处理 WAL），在副本上
   清空运行数据、保留配置。清之前先停服务，避免锁库。
3. **写启动器**：一个 GUI 小面板（tkinter）+ 命令行模式。核心职责是「自动选空闲端口 →
   拉起后端 → 等就绪 → 打开浏览器」，并只认自己目录下的后端进程。
4. **打包**：PyInstaller `--onefile --noconsole`。
5. **双场景终验**（见下方验收清单），不能只跑一遍 happy path。
6. **写两份文档**：`使用说明.txt`（含账号/调用信息/排查）+ `AI部署提示词.md`（自包含，
   步骤化，含常见报错处理）。
7. **打 zip**（`ZIP_DEFLATED, compresslevel=6`），并从 zip 解压到全新目录实跑一遍。

## 铁律与踩坑（每一条都是真金白银换来的）

### 1. Windows 上不能用 bind 探测端口是否空闲 ⚠️最重要
Windows 允许重复绑定：即使 `0.0.0.0:3000` 已被监听，再 bind `0.0.0.0:3000` 或
`127.0.0.1:3000` **都会成功**（Linux 不会）。用它判断端口空闲必然误判 → 服务启动
时 bind 失败秒退。

**正解**：端口占用一律读 `netstat -ano -p TCP` 的 LISTENING 结果（解析最后两列），
做个 2 秒短缓存避免反复调用。

**启动成功判定必须三条同时成立**：本目录的后端进程活着 + 该进程正在监听这个端口 +
接口有响应。只看「端口有响应」会把别人的服务误判成自己启动成功。

**兜底**：即使预判失误，也要在启动后检测进程是否秒退，失败就自动换下一个候选端口。

### 2. 打包 GUI 必须用带 tkinter 的 Python ⚠️
隔离环境的 managed Python 常常**没有 tkinter**。用它打的 exe：GUI 起不来、服务也不启动，
进程却还活着 —— 极难发现（表现为「双击没反应」）。

**检查**：`python -c "import tkinter; print(tkinter.TclVersion)"`，失败就换一个 Python。
Windows 上系统 Python（`%LOCALAPPDATA%\Programs\Python\Python3xx\python.exe`）一般都带。
给它单独建 venv 打包，不污染系统环境。

### 3. 沙箱里 Bash 命令结束会回收子进程
在 Bash 里启动的后台服务，命令一结束就被回收 → 跨命令验证「服务常驻」永远失败。
**正解**：「启动 → 验证 → 停止」放在同一条命令或同一个脚本内完成。

### 4. 沙箱内枚举窗口判断 GUI 不可靠
子进程窗口枚举不到（连隐藏窗口都看不见），但服务确实被拉起了。
**正解**：给启动器加 `--selftest`，在**进程内**建 Tk 窗口并把结果写文件（含
tkinter 版本、屏幕分辨率、窗口可见性、关键文件是否存在、端口占用情况）。
这个自检文件同时也交给使用者当排错工具。

### 5. 只认自己目录下的进程，绝不按进程名乱杀
用 `CreateToolhelp32Snapshot` + `QueryFullProcessImageNameW` 拿到每个候选进程的完整路径，
只有路径等于「本目录/后端.exe」才算自己的。否则 `taskkill /IM xxx.exe` 会误杀用户
正在跑的另一份同款服务（测试时尤其危险）。

### 6. 密码只能重置，不能反推
bcrypt 哈希（`$2b$12$...`）无法反推。给使用者的账号要么重置成新密码
（`bcrypt.hashpw(pwd.encode(), bcrypt.gensalt(rounds=12))` 写回库），要么清空用户表
让他自己初始化。**改副本，不动用户自己的库**。

### 7. 文档编码
`使用说明.txt` 用 **UTF-8 BOM**（`encoding='utf-8-sig'`）+ `\r\n` 换行，否则老版记事本
打开是乱码。文件名含中文没关系，zip 里 Python 会写 UTF-8 标记，Win10/11 资源管理器正常解压。

### 8. 开机自启优先用 HKCU Run 项
`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`，**不需要管理员权限**，
比计划任务简单、比启动文件夹快捷方式省事（不用建 .lnk）。配「静默启动」参数即可，
GUI 子系统程序本就无窗口。

**状态检测只看「注册表里这一项在不在」**，不要拿路径字符串去匹配——使用者把包放在
小写目录（`D:\xxx`）时匹配会失败，勾选框状态就错了。

## 最后一轮验收清单

- [ ] zip 从解压到全新目录，双击/静默启动成功
- [ ] 端口空闲时用默认端口；默认端口被占时**自动换端口**且不影响占用者
- [ ] 关键接口 200、能登录、配置项（渠道/账号池/模型）数量与预期一致
- [ ] 账号密码随包带齐（如适用）
- [ ] 开机自启：写入 → 状态能检到 → 取消 → 注册表无残留
- [ ] 自检报告内容正常（tkinter 正常 / 窗口可见性 True）
- [ ] 一键「停止服务」只停自己的进程，别处同款服务仍在跑
- [ ] 使用说明打开不乱码
- [ ] 用户本机的服务在测试后**已恢复运行**
